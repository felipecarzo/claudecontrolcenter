# CC-1120: o programa instalado que liga qualquer sessão ao cockpit

## O pedido, nas palavras dele

> "um software que eu instalo, a gente ja criou um mas eu nao sei pq ele não funciona. esse software captura tudo que
> sai daqui pro server da anthropic e com os hooks tambem consegue intervir."

Pronto, pelo backlog: sessão aberta no app, no terminal ou no claude.ai aparece no cockpit e recebe resposta dele, sem
rodar nada a mais.

## O software que já existe (medido em 23/11, 01h, por agente de leitura)

Programa que capture o tráfego para a Anthropic **nunca existiu**:
- O proxy foi pedido em 15/08 e trocado pelo gancho `anonimo-prompt`, que roda no envio do prompt
  (hooks/anonimo-prompt.mjs:3-30; docs/diario/2026-08-16.md:501-549). O CC-92 foi cancelado como órfão.
- Em src/, hooks/ e tools/ nenhum código usa `ANTHROPIC_BASE_URL`.

O que existe e está instalado é o cockpit:
- **Tarefa Agendada `AgentCockpit`**: roda no logon, chama `AppData\Local\AgentCockpit\src\arrancar.ps1`.
- **src/arrancar.ps1**: laço que religa o painel (porta 8099) e sobe a bandeja.
- **src/bandeja.ps1**: ícone com o estado da federação. Menu: abrir painel, reiniciar, "Adicionar pasta de
  projetos...", pausar sincronia, sair.
- Provável bandeja órfã: o processo dela parece ser de 22/11 12:13, anterior ao laço atual. Não conferido na tela.

**O defeito, do ponto de vista dele:** o programa faz o que foi feito para fazer, mas não alcança as sessões abertas
fora do painel. A recusa está em src/federacao.mjs:945 ("essa conversa não está num terminal aberto pelo painel desta
máquina").

## Pastas, VPS e documentos: o que já existe

- **Pastas de projeto:** `cc pastas adicionar|remover`, o menu da bandeja e o registro central
  `~/.claude/cockpit-projetos.json` (src/projetoRegistro.mjs).
- **Sincronizar com a VPS:** a federação empurra um resumo a cada 30 s. O git é por botão (src/sincronia.mjs, skill
  vps-sync), de propósito, porque cada máquina faz o próprio deploy.
- **Ler documentos:** src/roadmap.mjs, src/pastas.mjs (HANDOFF.md), src/observado.mjs.
- **Falta:** escrever na sessão do app (o resto deste plano).

## A pergunta decisiva: entregar texto a uma sessão que o painel não abriu

Cada Claude Code desta máquina se registra em `~/.claude/sessions/<pid>.json`, com `sessionId`, `status`,
`entrypoint`, `bridgeSessionId` (Remote Control) e `messagingSocketPath` (canal local).

- **(a) Intermediário pela ANTHROPIC_BASE_URL: impossível para o objetivo.** Só enxerga pedidos que a sessão faz;
  sessão ociosa não pede nada. Base URL fora da Anthropic desliga o Remote Control (CC-150).
- **(b) Ganchos: possível, falta medir.** O Claude Code 2.1.325 aceita em cada gancho a opção `asyncRewake`:
  "If true, hook runs in background and wakes the model on exit code 2". Um gancho pode esperar ao fundo a mensagem
  do cockpit e acordar a sessão. Vale para app, terminal e Remote Control. Não testado.
- **(c) Canal do Remote Control: possível em tese, não recomendado.** API de sessões não documentada, com o token
  OAuth dele. Não chamado.
- **(d) App do desktop: só de dentro.** As ferramentas de mensagem entre sessões existem só dentro de uma sessão;
  imitar o canal local seria protocolo interno.

## Três desenhos

**D1. O "ouvido" por gancho (recomendado)**
- Gancho global `hooks/ouvido.mjs`, com `asyncRewake: true` no SessionStart e no Stop (o Stop arma de novo a cada
  resposta). Espera a caixa da sessão; quando chega mensagem, imprime e sai com 2. Uma trava por sessão.
- No painel: o ramo "não achada" de `entregarMensagemRemota` grava na caixa em vez de recusar; o cadeado sai quando a
  sessão tem ouvido vivo; o texto passa pelo `limparTextoRemoto`.
- Entrega: responder pelo cockpit do PC ou da VPS qualquer sessão, sem ocupar a sessão.
- Custo: tamanho M. Limites: a mensagem chega como aviso de gancho, não como fala dele; depende de opção nova do
  Claude Code.

**D2. Retransmissão por uma sessão do painel**
- Uma sessão aberta pelo painel recebe o texto e repassa pela ferramenta de mensagem entre sessões.
- Custo: gasta tokens por mensagem, uma sessão precisa ficar viva, pede mudar a configuração `crossSessionInbound`.
  Tamanho P.

**D3. Skill que deixa a sessão escutando**
- `/escutar` roda em laço um comando que espera mensagem e volta a esperar.
- Funciona hoje em qualquer lugar. Custo: a sessão fica ocupada e cada volta gasta tokens. Tamanho P.

  Remote Control, VPS, painel rodando como administrador.

## A entrada do settings.json (para ele aplicar)

Acrescentar um grupo novo em cada evento, sem apagar os que já estão lá. Caminho do PC; na VPS troca pelo do repo lá.

```json
"SessionStart": [
  { "hooks": [ { "type": "command", "command": "node", "args": ["D:/Documentos/projetos/cockpit/hooks/ouvido.mjs"], "asyncRewake": true, "timeout": 86400 } ] }
],
"Stop": [
  { "hooks": [ { "type": "command", "command": "node", "args": ["D:/Documentos/projetos/cockpit/hooks/ouvido.mjs"], "asyncRewake": true, "timeout": 86400 } ] }
]
```

Sem `asyncRewake` o Stop esperaria horas travando a sessão. Depois de registrar, religar o painel de cada
máquina para ele carregar `src/ouvido.mjs`.

## Riscos

- Texto de fora que acorda o modelo é porta de entrada: só o painel autenticado escreve na caixa, o ouvido só lê a
  caixa da própria sessão, teto de 4000 caracteres.
- O painel roda como administrador e o app não: a caixa precisa estar numa pasta que os dois escrevam. Não conferido.
- Depois de mexer em src/, religar o painel de cada máquina.
