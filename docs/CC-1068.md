# CC-1068: o modo Regente do arquiteto

Pedido dele em 20/10, 07:05: *"Vamos criar um agente só pra tocar os projetos? (...) eu quero um agente um chat que olhe
as tarefas e abstraia dela, decida coisas etc, a gente vai treinando ele p aprender a tomar decisões estruturais, de
segurança, de design etc"*. E: *"Ele não precisa parar sozinho a não ser que a gente ligue uma dessas travas (...) ou se
o projeto é de risco"*.

Decisões dele (caixa de pergunta, 07:20): é um MODO do arquiteto (CC-867), não agente novo; as regras aprendidas moram
por projeto E num caderno global; executor é o Claude Code sem permissões; piloto no coemotorista por um ciclo, depois
os seis projetos do plantão.

## O que é

O arquiteto hoje (modo Product Owner) lê o estado, propõe UM passo pelo modelo, confere por contrato e PERGUNTA a ele.
O modo Regente faz o mesmo ciclo, mas **decide no lugar dele** pelo critério (um caderno de regras que cresce com as
correções dele), escreve na conversa "decidi X porque Y, corrija se discordar", e **não para**: um timer do sistema
chama o passo seguinte sempre que não há obra rodando.

Nome na tela: continua **Arquiteto**. "Regente" é o modo (um nome por coisa, regra de escrita 3).

### M2. O arquiteto no modo Regente (`src/arquiteto.mjs`, `src/web.mjs`)

1. `pedidoDeProposta(estado)`: quando `estado.regras` existe, acrescentar antes do ESTADO: "REGRAS DO DONO (obrigatórias,
   aprendidas com ele): <texto>". `lerEstado` passa a incluir `regras: regrasDe(cwd)` e `regente: ler(cwd).ligado`.
2. `passo()`: depois de `registrarPergunta(cwd, proposta)`, se `ler(cwd).ligado` e a ficha não foi respondida pelo
   caminho automático que já existe:
   - se a proposta é "pedido" cujo item `exigeDele` (procurar o item por `proposta.daFila` ou `itemDoBacklog`): mover o
     item para a fila dele (`B.mover(id, 'DE', { porque: 'exige o Felipe: ...' })` ou o estado que o backlog usa para
     "esperando ele"; o executor confere qual), responder a ficha com a opção negativa ("Não", "depois", a que não
     executa) e `automatico: 'regente: exige o Felipe (conta, aparelho, root ou deploy)'`, e chamar `passo` de novo
     uma vez (`voltou: true`) para propor outra coisa;
   - senão `decidir(cwd, proposta, estado)`; com decisão, `responder(cwd, ficha.id, decisao.escolha, { automatico:
     'regente: ' + decisao.porque })`; devolver `{ pergunta: fechada, proposta, automatico: true, regente: decisao }`.
   - o teto `podeAutomatico` NÃO segura o Regente (ele pediu não parar); fica `ler(cwd).teto` (0 = sem teto) para quando
     ele quiser uma trava.
3. `seguir()` (quem trata o resultado do passo): com `regente`, postar na conversa do arquiteto UMA mensagem de sistema:
   "Regente: decidi <escolha> em "<titulo da proposta>". Por quê: <porque>. Corrija escrevendo aqui (regra: ... para
   virar regra deste projeto; geral: ... para valer em todos)". Depois seguir como seguiria com resposta dele:
   `fechada.executar` dispara `executarFicha`; `fechada.fazer` o caminho de "Fazer:"; revisão aprovada fecha o ciclo e
   chama `passo` de novo. Sem nada a fazer (socorro sem fila, decisão null): postar "Regente: sem passo possível
   (<motivo>); espero você" e parar. Tudo o que hoje a rota do painel faz ao receber a resposta dele, o `seguir` faz
   aqui, no mesmo processo, para o ciclo não depender de clique.
4. `src/web.mjs`, `seguirArquiteto()`: antes de virar item, `const r = ehRegra(texto)`; se r, `aprender(cwd, r.texto,
   { geral: r.geral })`, gravar na conversa "Regra anotada (<projeto|geral>): <texto>. Vale a partir do próximo passo."
   e disparar `--passo` sem criar item. Também em `responderArquiteto()`: texto dele com `ehRegra` vira regra ALÉM da
   resposta (a resposta continua sendo a escolha).
5. Rota `POST /api/regente { projeto|cwd, ligado: true|false, risco? }` -> `ligar`/`desligar`; ao ligar, dispara
   `--passo` se não houver obra rodando (`obraRodando`) nem pergunta aberta. `GET /api/regente?cwd=` -> `ler(cwd)` e
   as últimas 5 linhas de cada caderno. Comentário de duas linhas citando CC-1068; perto de `/api/arquiteto/comecar`.
6. `cc regente ligar|desligar|estado|regra "<texto>" [--geral]` em `cc.mjs`, para o terminal e para o timer (M4).

### M5. Piloto (o coordenador, esta sessão)

1. Avisar a sessão interativa do coemotorista para fechar o item atual, commitar e PARAR (duas mãos no mesmo projeto
   é o acidente que o Routia impede). Desligar a ordem do despertador para ela (marcar no `plantao-ativo`? não: o
   despertador manda ordem a sessão parada; a sessão do coemotorista será ENCERRADA pelo painel depois do commit).
2. `cc regente ligar --pasta ~/projetos/coemotorista`; ler `~/logs/regente-coemotorista.log` e a conversa do
   Arquiteto; acompanhar UM ciclo: decisão, obra do maestro, prova, revisão decidida, commit, próximo passo.
3. Escrever uma correção de teste ("regra: ...") e conferir que entrou no caderno e no pedido seguinte.
4. Só então ligar nos outros cinco, um por um, e encerrar as sessões interativas deles do mesmo jeito.
