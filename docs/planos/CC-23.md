# CC-23: Histórico rico por projeto

**Modelo:** Sonnet. O plano abaixo já tomou as decisões de formato, que era a
parte cara.
**Depende de:** nada. **Destrava:** CC-24, CC-33, CC-41.

---

## O problema, em uma frase

Task fechada **some**. Ela sai da lista de to-dos e não vira registro de nada,
então "o que este projeto produziu" não tem fonte, e é isso que trava o digest
(CC-24), o delta desde a última visita (CC-33) e os sinais do ciclo (CC-41).

## O que existe hoje

`src/historico.mjs` (100 linhas) copia os jobs vistos para
`~/.claude/control-center-historico.json` a cada varredura, só quando algo muda.
Guarda por **job**, com `guardavel()` selecionando os campos: `todos`, `feitoEm`,
`niveis`, `estimativas`, `tokens`, `createdAt`, `updatedAt`, `desde`, `visto`.

Isso cobre o que a aba de preço precisa. Não cobre "o que aconteceu neste
projeto", porque:

1. **Não guarda `cwd`.** Sem o caminho, não dá para cruzar o job com o `git log`
   nem com o `docs/ROADMAP.md` daquele projeto. `guardavel()` tem `project`
   (nome), que não é caminho.
2. **`feitoEm` é podado antes de chegar aqui.** `marcarConclusoes()` remove do
   mapa as entradas cujo texto não está mais na lista de to-dos; como
   `arquivar()` sobrescreve `h.jobs[g.id]` inteiro, a poda vaza para o histórico
   e o carimbo de conclusão **se perde**. É o bug central: a única prova de "isto
   foi concluído às 14h32" é apagada quando o agente reescreve a lista.
3. **É indexado por job**, e job é efêmero. A pergunta do Felipe é por projeto.

## O que fazer

### 1. Guardar `cwd` no `guardavel()`

Uma linha. Sem isso nada mais funciona.

```js
cwd: j.cwd || null,
```

### 2. Fazer merge do `feitoEm`, nunca sobrescrever

Em `arquivar()`, onde hoje está `h.jobs[g.id] = { ...g, desde, visto }`:

```js
h.jobs[g.id] = {
  ...g,
  // `marcarConclusoes()` poda o feitoEm quando o agente reescreve os to-dos.
  // Sobrescrever aqui propagaria a poda pro histórico e apagaria o carimbo -
  // que é a única prova de quando a tarefa fechou.
  feitoEm: { ...(antes?.feitoEm || {}), ...g.feitoEm },
  desde: antes?.desde || g.createdAt || agora,
  visto: agora,
}
```

Faça o mesmo para `niveis` e `estimativas`: são chaveados por texto de to-do e
sofrem da mesma poda.

### 3. Uma função nova: `marcosDe(projeto, { desde })`

Exportada de `historico.mjs`. Devolve os marcos daquele projeto, ordenados por
tempo, **derivando do que já está guardado**, sem escrever arquivo novo, sem
spawn, sem rede:

```js
/**
 * O que aconteceu neste projeto, em ordem. Deriva do histórico que já existe:
 * não escreve nada e não custa nada além de ler um JSON.
 */
export function marcosDe(projeto, { desde = 0, jobs = null } = {}) { … }
```

Cada marco é `{ em, tipo, texto, jobId }`, com **três tipos, e só três**:

| tipo | de onde sai | texto |
|---|---|---|
| `todo` | `feitoEm[texto]` de cada job do projeto | o texto do to-do |
| `agente` | `desde` do job | `subject` do job |
| `entrega` | `updatedAt` de job com `status: done` | `subject` do job |

**Não invente tipo novo agora.** Commit e roadmap entram no CC-24 e no CC-35,
que leem do disco do projeto, aqui é só o que o histórico já tem. Marco de
commit exigiria spawn de `git`, e isso não pode viver numa função que o cockpit
chama.

### 4. Uma rota, sob clique

Em `web.mjs`, no padrão de `/api/cockpit` (que é o barato, sem spawn):

```js
if (url.pathname === '/api/marcos') {
  const projeto = url.searchParams.get('projeto')
  const desde = Number(url.searchParams.get('desde')) || 0
  return send(res, 200, { marcos: marcosDe(projeto, { desde }), at: Date.now() })
}
```

## Armadilhas que se aplicam

- **`feitoEm` fica fora da lista de to-dos**, e é chaveado por **texto**. Nunca
  reescreva `t.text`: `feitoEm`, `niveis`, `estimativas` e `explicacoes` dependem
  dele como chave.
- **`~/.claude/jobs` é efêmero**: é justamente por isso que este módulo existe.
  Não vá buscar o dado lá.
- **Nunca escrever dentro de `~/.claude/jobs/`.**
- **`arquivar()` nunca lança.** Mantenha o `try/catch` engolindo: falhar ao
  arquivar não pode derrubar o painel.
- **O rateio de tempo entre tarefas continua por igual** mesmo com `feitoEm`
  carimbado. Não mexa nisso aqui; é decisão registrada nos limites aceitos.

## Como verificar

1. `npm test` verde, com asserts novos: `marcosDe` devolve vazio para projeto
   desconhecido; um job com dois `feitoEm` gera dois marcos `todo`; e **o teste
   que importa**, arquivar duas vezes, a segunda com `feitoEm` podado, e provar
   que o carimbo antigo **sobreviveu**.
2. Prova real, não só teste:
   `curl "http://localhost:8123/api/marcos?projeto=proj_controlcenter"` tem que
   trazer marcos com data plausível.
3. Confira que `historico.json` ganhou `cwd` nos jobs novos:
   `node -e "…readHistorico()…"`.

## O que NÃO fazer

- Não criar arquivo novo de histórico. O `control-center-historico.json` já é o
  lugar, e duplicar daria duas verdades.
- Não varrer disco nem chamar `git` dentro de `marcosDe`. Ela vai ser chamada
  pelo cockpit; tem que ser tão barata quanto `porProjeto()`.
- Não mudar o formato do que já está guardado de um jeito que invalide o arquivo
  existente. Campo novo entra opcional, e job antigo sem `cwd` continua válido.
