# CC-35: `git log --since` na abertura do projeto

**Modelo:** Sonnet. **Depende de:** nada. Casa bem com CC-33.

---

## O problema

"O que mudou desde que saí" tem resposta pobre hoje: `sinais.arquivos` do
`tempo.mjs` é **contagem** (`edicoes.size`), não lista de caminhos. A resposta
rica está no `git log`, e ninguém a lê.

## O que fazer

Módulo pequeno, ou função em módulo existente, que roda `git log` numa janela:

```
git log --since=<ISO> --pretty=format:%H%x09%at%x09%s --numstat
```

Devolve por commit: hash, quando, assunto e os arquivos tocados.

**Sob clique, nunca em timer.** Rota própria (`/api/git?projeto=&desde=`), no
padrão de `/api/vps/atualizar` e `/api/processos`: spawn não entra no stream
de 2s.

## Armadilhas que se aplicam

- **Use `quietAsync`, nunca `quiet`.** `quiet` é síncrono (`execFileSync`) e
  congela o event loop, e com ele o stream dos agentes. Medido: uma leitura de
  1s trava tudo por 1s.
- **`execFile` não usa shell.** Passe cada argumento como elemento do array. Não
  monte string com aspas.
- **Caminho do projeto**: use o `cwd` do histórico (CC-23) ou `findProjects()`.
  Nunca fixe caminho de máquina no código: a base é descoberta.
- **Projeto sem git, ou pasta que não existe**: devolva vazio com um motivo, não
  erro na tela. `quietAsync` devolve `ok:false` em silêncio no timeout, e já
  houve caso de `null` intermitente que parecia bug de parsing e era timeout.
  Dê timeout folgado e reporte quando estourar.
- **Não cruze com `tempo.mjs`.** O relógio não sabe qual commit saiu; o motor de
  gráficos recusa esse cruzamento de propósito.

## Como verificar

1. Rodar contra este próprio repositório, que tem commits de hoje, e conferir
   que os arquivos batem com `git show --stat`.
2. Rodar contra um projeto sem git e confirmar que a tela mostra "sem
   histórico", não erro.
3. Medir o tempo da chamada e anotar no comentário do módulo. Se passar de ~2s,
   o cache tem que existir antes de a rota entrar na tela.
