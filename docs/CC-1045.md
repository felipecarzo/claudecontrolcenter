# CC-1045: os guardas do fim de resposta num processo só

## O problema, medido em 12/10

- 32 ganchos de `Stop` registrados em `~/.claude/settings.json`; o Claude Code roda todos juntos ao fim de cada resposta.
  A máquina tem 6 núcleos. Cada um, sozinho, leva 0,17 a 0,8 s; juntos, cada um leva ~4,3 s, porque são 32 processos
  Node nascendo ao mesmo tempo e carregando os mesmos módulos. Mediana da espera: 5,7 s (7 dias); 88 de 424 respostas
  passaram de 10 s.
- O guarda do quadro já foi consertado à parte (2,5 s para 0,5 s: pedia a ordem pelo git sem precisar).

## A decisão dele

*"junta todos num processo só, e toma cuidado p não colocar nada que possa ativar as travas do claude, uns bloqueios
com palavras que ele bloqueie"*. Contexto: ele já viu o aviso do Claude sobre extração de raciocínio e desconfiou de um
gancho nosso. Levantado em 12/10: nenhum texto que os guardas devolvem fala de raciocínio, pensamento, "thinking",
"reasoning" ou cadeia de pensamento. O programa novo não pode introduzir nada disso, e um teste garante.

## O desenho (mínima mudança nos guardas)

`hooks/parada.mjs`, um programa só, registrado no lugar de 31 dos 32 (fica de fora o `~/.pixel-agents/hooks/claude-hook.js`,
programa de terceiros, que continua registrado sozinho).

1. Lê a entrada (stdin) UMA vez.
2. Para cada guarda da lista (ordem fixa, a mesma do settings hoje), em SEQUÊNCIA, no mesmo processo:
   - prepara o "ambiente" do guarda: `fs.readFileSync(0)` devolve a entrada guardada; `process.exit(n)` vira um sinal
     (exceção própria) que encerra só aquele guarda com o código n; `console.log/error`, `process.stdout.write` e
     `process.stderr.write` são capturados para aquele guarda;
   - `await import(url do guarda)` com uma busca (query) única, para o módulo rodar de novo se preciso;
   - teto por guarda (8 s): passou, registra "cortado" e segue para o próximo;
   - restaura o ambiente.
   Os módulos de `src/` que os guardas importam ficam em cache entre eles: é aí que está o ganho.
3. Junta os resultados como o Claude Code faria com ganchos separados: se algum guarda saiu com código 2, o programa sai
   com 2 e o stderr é a soma dos stderr dos que barraram, cada um com uma linha de cabeçalho com o nome do guarda; se
   algum imprimiu JSON de decisão em stdout, preservar o formato (ler como cada guarda devolve hoje e espelhar).
   Sem barrar ninguém: código 0, e o que os guardas imprimiriam em stdout segue igual.
4. Os guardas continuam rodando SOZINHOS do mesmo jeito (nenhum precisa mudar para isso). Se algum guarda precisar de
   mudança (por exemplo, um `process.exit` dentro de `try` que o sinal não atravessa), a mudança é mínima e o teste de
   equivalência é o juiz.
5. O registro de cada guarda no monitor de hooks: a aba Hooks lê os nomes dos ganchos das conversas. Com um programa só,
   ela passaria a ver só "parada". O programa novo grava, para cada guarda, nome, tempo, código e se barrou, num arquivo
   de medidas no abrigo (`~/.local/share/agent-cockpit/`, respeitando `CC_HOME`), e `src/hooksMonitor.mjs` passa a ler
   esse arquivo para continuar mostrando por guarda. (Pode ficar para um segundo passo, mas registre se ficar.)

## Prova de que nada mudou (obrigatória)

`test-parada.mjs`: entradas REAIS de fim de resposta (montar a partir de conversas recentes em `~/.claude/projects`,
só leitura: `transcript_path`, `session_id`, `cwd`, `stop_hook_active` false e true), pelo menos 6, de projetos
diferentes. Para cada entrada e cada guarda: rodar o guarda SOZINHO (processo próprio, como hoje) e DENTRO do programa
novo, cada um com uma casa temporária NOVA (`CC_HOME` e o abrigo apontando para pasta temporária), e comparar código
de saída e texto (stderr e stdout). Tem de ser idêntico. Nunca rodar guarda com a casa real dele: guardas lembram o que
já avisaram, e o teste sujaria esse dado. Também: o texto juntado nunca contém "racioc", "pensament", "thinking",
"reasoning", "chain of thought"; e o tempo do programa novo (medido) fica abaixo de 1,5 s.

## Registro

A troca no `~/.claude/settings.json` (31 ganchos saem, 1 entra) é feita por quem coordena, depois da prova, com
cópia do arquivo antes. O catálogo (`src/hooksCatalogo.mjs`) continua valendo por guarda (ligar e desligar cada um).
