# CC-1052: o painel "a conversa" da aba Sessões vira o Claude Code em forma de app

Pedido dele em 11/10, com print do app do Claude Code no celular: *"ao invés de ser só essa conversa, eu quero que tenha a
opção de eu controlar o Claude como se fosse a sessão do Claude aqui, só que com uma formatação bonitinha, igualzinho um
Coderoom (...) eu sentir que to usando o claude code com as mesmas funções, botões etc"*. A forma ficou por minha conta.

## Decisão de forma

O painel "a conversa" (aba Sessões, modo lista) deixa de ser só leitura e vira a sessão em forma de app, falando com a
MESMA sessão de terminal (tmux) por trás, pelos caminhos que já existem. Nada de sessão paralela, nada de `claude -p`.

De cima para baixo:

1. **Faixa do topo, uma linha só** (nada empilhado): estado (trabalhando / esperando você), modo atual lido da tela
   (manual, aceitar edições, auto, plano), modelo (do .jsonl) e esforço (da tela), e os botões **parar** (Esc),
   **modo** (Shift+Tab, mostra o próximo) e **terminal** (abre o `c2Terminal`, que já existe).
2. **Conversa formatada**: falas dele e do Claude com markdown (reusar `gateFormatar` do Coderoom). Entre falas do Claude,
   as ferramentas viram um `<details>` recolhido, "Executou 3 comandos, leu 2 arquivos, editou 1", com a lista
   nome + alvo dentro (igual `gate-cmds` do Coderoom). Rola sozinho para o fim quando chega fala nova
   (`c2ConversaRolar` já existe), menos se ele rolou para cima.
3. **Pergunta ou permissão pendente desta sessão**: o mesmo formulário que o cartão já usa (`c2DecForm` / `c2Aviso` do
   cartão `dec` daquela conversa), mostrado logo acima do campo, como no app.
4. **Campo de escrever** (textarea, cresce até 6 linhas): Enter envia, Shift+Enter quebra linha. Digitar `/` no começo
   abre a lista de comandos (reusar a lista de `GET /api/coderoom/comandos` e o jeito do `gateSug*`). Botão enviar
   redondo à direita, microfone se o campo de responder já tiver (reusar). Se a tela mostra rascunho no campo do
   terminal, avisar ("há texto digitado no terminal: ...").
5. Enquanto o painel está aberto e a sessão escolhida, relê conversa e tela **a cada 2 s** (hoje 10 s); fechado, nada.

Celular (390px): a faixa do topo quebra em no máximo duas linhas com os botões à direita; o campo fica preso embaixo.

## Contrato servidor ↔ tela

### `GET /api/sessao/conversa?conversa=<id>&app=1`
Igual hoje, mais `itens` (só com `app=1`):
```
{ falas: [...como hoje...],
  itens: [ { tipo: 'voce', texto, em },
           { tipo: 'agente', texto, em },
           { tipo: 'ferramentas', em, lista: [ { nome: 'Bash', alvo: 'npm test' }, { nome: 'Read', alvo: 'src/x.mjs' } ] } ],
  modelo: 'claude-opus-5-5' | null }
```
- `itens`: até 80, na ordem; ferramentas seguidas do mesmo turno se juntam num bloco só; `alvo` curto (até 120 chars:
  `command`, `file_path` relativo ao cwd, `pattern`, `url`, `description` ou `prompt` de Agent cortado).
- Fora: sidechain, isMeta, `<command...>`/`<system...>`, tool_result. AskUserQuestion vira fala do agente com o texto
  das perguntas (como hoje).
- `modelo`: o `message.model` da última fala do assistente.
- Função pura `itensDaConversa(texto, { parcial, limite })` em `src/cockpit2.mjs`, exportada e testada; cache igual ao de
  `conversaRecente` (chave separada).

### `GET /api/sessao/tela?conversa=<id>`
`{ ok, trabalhando, modo, esforco, rascunho, tmux }`, lido de `tmux capture-pane -p` da sessão daquela conversa
(achar por `estadoRC`, como `decisao.mjs` faz). Função pura `lerRodape(texto)` exportada e testada. Amostras reais:
```
❯ pode apagar a cópia de medição
────────────────────────
  ⏵⏵ auto mode on (shift+tab to cycle) · ← for agents
```
```
❯ 
────────────────────────
  ⏸ manual mode on · ⧉ 3 · ← for agents
```
e de outra: `◖ medium · /effort`. `modo` ∈ `manual | aceitar | auto | plano | null` (`accept edits on` = aceitar,
`plan mode on` = plano, `bypass` = auto também serve); `trabalhando` = a tela tem `esc to interrupt`;
`rascunho` = o texto depois de `❯ ` na última linha de prompt, se não vazio; `esforco` = palavra antes de `· /effort`.

### `POST /api/decisao/tecla` `{ conversa, tecla }`
`tecla` ∈ `{ parar: 'Escape', modo: 'BTab' }` (lista fechada; qualquer outra recusa). Mesma defesa das outras rotas
POST (`pedidoDeFora`). Manda `tmux send-keys -t <sessão> <tecla>`. Devolve `{ ok, tela }` com o rodapé depois de 400ms.

### Envio de texto
Continua `POST /api/decisao/mensagem`. Atenção: texto que começa com `/` (comando de barra) não aparece no .jsonl como
fala do usuário; se `enviarMensagem` confere a chegada pelo .jsonl, para comando de barra a conferência é pela tela
(o campo do terminal ficou vazio) ou pelo `<command-name>` no .jsonl. Medir antes de mudar.
