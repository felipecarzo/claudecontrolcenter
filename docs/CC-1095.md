# CC-1095: prova automática

Pedido dele em 18/11: *"esses testes são muiuto complicados de eu fazer, tem como a gente automatizar testes, trazer prints e informacoes pra eu avaliar sem sair daqui?"*.
Escopo escolhido por ele: só os 25 itens em prova cuja conferência é `olho:` (olhar uma tela). Os 96 de `dele:` (usar a coisa) ficam para uma segunda rodada.

## O que já existe e vira base

- Baralho de cartas: `docs/cartas/<deck>.json` de cada projeto (`src/cartas.mjs`, campos `id titulo pergunta olhe passos img link opcoes`).
  Votos em `/api/cartas/votar`. A tela é o "Revisar um por um".
- Print do painel em 390 px: `test-estreito-v2.mjs` serve a página do disco, intercepta `https://cockpit.carzo.com.br/**` e deixa os GET irem
  para o painel em `127.0.0.1:5180`; POST responde `{"ok":true}` e nunca grava.
- Chromium local em `~/.cache/ms-playwright` (comando `print-logado`), sem chave.

## O desenho

1. **Receita por item** (`dados/provas-receitas.json`): para cada ID em prova com `olho:`, a tela (`view-...`), o estado a abrir
   (aba, seleção, largura) e o seletor do que mostrar. Sem receita, o item sai na lista "sem print automático" com o motivo; nunca carta vazia.
2. **Motor** (`src/provaAutomatica.mjs`): lê o backlog, pega os itens em prova com `olho:`, abre a receita no Chromium local,
   espera o conteúdo estabilizar (não tempo cego), tira o print, grava em `docs/cartas/provas/<ID>.png`.
3. **Deck** `docs/cartas/provas-do-backlog.json`: uma carta por item. `olhe` = o `conferir` do item; `passos` = o que o robô fez;
   `img` = o print; `opcoes` = Aprovo / Não aprovo.
4. **Voto vira estado**: Aprovo move o item de prova para OK com a prova "aprovado por ele no Revisar um por um, carta X, data".
   Não aprovo devolve o item para EM com a nota dele. Só o voto dele muda o estado; o robô nunca aprova.
5. **Comando**: `node cc.mjs prova automatica [--item CC-1087] [--ensaio]` (roda um item por vez; a VPS está sempre carregada).

## Regras

- Print só vale se a largura for conferida (armadilha do 390 px: a faixa do topo tem o sino em 316 de x).
- Nenhum POST real: o painel mostra dados reais, mas a coleta nunca grava neles.
- Uma carta só por item; rodar de novo substitui o print, não duplica a carta.

## Como se confere

`olho:` abrir o Revisar um por um e ver a carta do CC-1087 com print em 390.
`auto:` `node test-prova-automatica.mjs` (a receita dá carta válida em `validarDeck`, o print existe e tem a largura certa, o voto Aprovo move o item).

## Ordem de construção

1. Protótipo com uma receita (CC-1087) e o print. Prova de que o caminho fecha.
2. Deck + voto virando estado.
3. Receitas dos outros 24 itens `olho:`; os que não derem entram na lista de "sem print automático".
